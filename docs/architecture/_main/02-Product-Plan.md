# Coriven — Product Plan

> Synthesized from `docs/planning/2026-06-24-coriven-master-blueprint.md` (§17 roadmap, §19 open decisions). The blueprint governs on conflict.

## Project Overview

### Project Name

Coriven (operating under MealPrepForge LLC as a DBA).

### Project Description

A personal Life OS: an AI assistant with a goal hierarchy, compounding persistent memory, approval-gated external actions, and desktop notifications. Built personal-first, productizable without a rewrite.

### Problem Statement

Existing tools track *what* but not *why*, and AI assistants forget context between sessions and ignore standing "never do X" rules. There is no integrated system that reasons over goals, remembers people/projects/preferences over months, and reaches the user proactively while keeping humans in control of external actions.

### Target Users

- **Primary users**: The owner (Roy) as the first daily driver.
- **Secondary users**: Beta cohort post-Phase 3 (overwhelmed professionals; planner enthusiasts).
- **Stakeholders**: MealPrepForge LLC (business/payments); Anthropic/Supabase/OpenAI/Upstash/Vercel/Stripe as platform dependencies.

## Project Scope

### In Scope

- [x] Goal hierarchy: Life Area → Goal → Project → Task → Reminder.
- [x] Tasks + reminders (separate `task_reminders` table — as-built, §7.4 blueprint).
- [x] Chat engine with tool use and per-user tool permissions.
- [ ] Three-layer memory (entity profiles + semantic memory + summaries), then the async Sentinel.
- [ ] Deterministic daily briefing + momentum + stale-goal nudges.
- [ ] Communications: email triage, calendar, approval queue, audit log; n8n as replaceable worker.
- [ ] Proactive: pattern detection, weekly review, cross-context queries.
- [ ] Productization: Stripe tiers, onboarding, PWA + Web Push; Tauri tray (Windows + Mac).
- [ ] (Conditional) lightweight behavioral-constraint registry + pre-action check (§19.1).

### Out of Scope (now)

- [ ] Bi-temporal / graph memory (Graphiti-style) — deferred until usage justifies (§18.5).
- [ ] Medication tracking — deferred; task reminders assumed sufficient for now (§19.2).
- [ ] Voice interface, local LLM fallback, MCP server exposure, team/shared contexts, custom recurrence intervals (§18).
- [ ] Capacitor native mobile — only if PWA usage shows demand.

### Success Criteria

1. A reminder set 2 minutes out fires a native notification within 5 minutes with the browser closed; Snooze/Dismiss work.
2. Cross-session recall: "my sister Sarah lives in Denver" (session A) → "I'm visiting my sister" (session B) → Coriven mentions Denver and offers flights; supersession works when she moves.
3. Daily briefing surfaces a goal's momentum and today's linked task; stalled goals nudge after 14 days.
4. (Comms) Connect Gmail → emails classified within 15 min → drafted reply lands in approvals → approve → sent.

## Feasibility Assessment

### Technical Feasibility

#### AI/ML Requirements

- [x] LLM integration (Claude Sonnet for chat, Haiku for extraction/triage).
- [x] Vector database (pgvector in Supabase).
- [ ] Real-time processing — chat streaming yes; memory extraction is async (Sentinel).
- [x] Pre-trained models sufficient; no custom training.

#### Data Requirements

- [x] Data generated by the owner's own usage (no external training corpus).
- [x] Privacy/compliance: per-user RLS; encrypted OAuth tokens; no email bodies stored.
- [x] Storage strategy defined (Supabase Postgres + pgvector; Upstash for Sentinel cache).

#### Infrastructure Requirements

- [x] Cloud hosting: Vercel (web) + Supabase + Upstash; tray installed locally.
- [x] Scalability: per-user scale; RLS multi-tenancy already in place.
- [x] Security: zero-trust inputs; approval queue; audit log; AES-256-GCM for tokens.
- [x] Integration points mapped: Gmail, Google Calendar, n8n, Stripe.

### Risk Assessment

#### High Risk Items

1. **Risk**: Behavioral-constraint adherence remains unreliable (~42.5% baseline).
   - **Impact**: High. **Probability**: Medium.
   - **Mitigation**: Dedicated constraint layer, richly-encoded rules, pre-action check; ship as v1 and measure (§19.1 option b).

2. **Risk**: Sentinel adds complexity (async + Upstash) before value is proven.
   - **Impact**: Medium. **Probability**: Medium.
   - **Mitigation**: Ship the synchronous Memory MVP (2a) first; Sentinel as 2b only after the MVP validates value (§19.3).

#### Medium Risk Items

- Tauri signing/notarization cost and CI complexity (Apple Developer $99/yr, Windows code-signing cert) — accepted now to avoid building tray features twice (§13.4 blueprint).
- Adding OpenAI as a second AI vendor alongside Anthropic (§19.7) — accepted for cheap embeddings.

#### Dependencies

- [ ] Anthropic, Supabase, OpenAI, Upstash, Vercel, Stripe availability and pricing.
- [ ] Gmail/Calendar OAuth approval for the comms phase.

## Technology Stack Assessment

### AI/ML Stack

- **Primary LLM**: Anthropic Claude Sonnet (`claude-sonnet-4-6`) — chat + tool use.
- **Extraction LLM**: Anthropic Claude Haiku (`claude-haiku-4-5-20251001`) — memory/entity extraction, email triage.
- **Vector store**: pgvector in Supabase.
- **Embedding model**: OpenAI `text-embedding-3-small` (1536 dims).

### Application Stack

- **Framework**: Next.js 15 (App Router) — UI + API routes + Server Actions.
- **Language**: TypeScript (strict everywhere).
- **Database**: Supabase (Postgres + Auth + RLS).
- **API design**: REST API routes; SSE for chat streaming.
- **Styling**: Tailwind CSS 4.

### Infrastructure Stack

- **Hosting (web)**: Vercel (auto-deploy from `main`).
- **Cron**: Vercel Cron (briefing, email poll, pattern detection), `CRON_SECRET`-protected.
- **Cache**: Upstash Redis (Sentinel context, TTL-bounded).
- **Tray**: Tauri (Rust core + system webview) → Windows `.exe` + Mac `.app`; thin shell over the API.
- **Automation**: n8n self-hosted (comms phase) — execution worker for approved actions only.
- **Payments**: Stripe via MealPrepForge LLC (DBA).

### Integration Requirements

- [ ] Gmail API (email metadata; bodies on demand).
- [ ] Google Calendar API (events; writes via approval).
- [ ] n8n webhook (post-approval execution).
- [ ] Stripe (subscriptions, webhooks).
